# Statistics v2 — Wave 1 common rules (pure logic)

Frontend root: `/home/nicola/Desktop/FinanceWebApp/frontend` (React 19 / TS strict / Vitest).
- Pure TypeScript modules in `src/dashboard/statistics/`, no React, no kit import, no context.
- Tests in `src/__tests__/dashboard/statistics/<module>.test.ts` (Vitest: `import { describe, it, expect } from "vitest"`).
  Build Transaction fixtures inline with a small `tx(date, amount, type, extra?)` helper; required fields of
  `Transaction` (`src/types/domain.ts`): `id, name, tag: {name, icon, colorHex}, amount, type, transactionDate`.
- `Transaction.amount` is always positive in wallet currency; `type: "INCOME" | "EXPENSE"`;
  `transactionDate` is an ISO string ("2026-03-01" or "2026-03-01T10:00:00"); `subscriptionId?` set = generated by a subscription.
- Never `new Date(isoString)` to get year/month (UTC shift). Use `txYearMonth` from `./statsPeriod.ts` (parses the
  "YYYY-MM" prefix; month 0-based).
- Anything depending on "today" takes an explicit `today: Date` parameter (no `Date.now()` inside) so tests are stable.
- Amounts are plain numbers; no rounding except where the spec says (display strings).
- English only (code, comments, copy). Relative imports with `.ts` extension like the folder does. Comments only for a non-obvious why.

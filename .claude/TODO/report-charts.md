## Constraints (read before designing)
- [ ] **No JavaScript, no chart kit**: reports are server-rendered HTML → PDF with
      `openhtmltopdf-pdfbox` (no SVG support in the current setup) and an HTML **email** body
      (Gmail/Outlook strip SVG and most CSS). Build the calendar and weekday bars from
      **HTML tables with inline background colours / widths**, which work in both.
- [ ] **Savings-rate ring** needs SVG in the PDF: either add `openhtmltopdf-svg-support`
      (Batik, heavier dependency) or show it as a big % plus a horizontal bar. **DECISION**
      for Nicola. In the email body, use the big % only.
- [ ] Aggregation lives in `ReportAggregator` (pure, unit-tested): daily spending totals for
      the period, weekday averages (exclude transactions generated by a subscription),
      savings rate = (income − expense) / income (undefined when income = 0 → hide the chart).
- [ ] Colours: reuse the report's palette; keep the 5-step calendar scale monotonic in
      lightness so it survives greyscale printing; every chart gets a text label (no
      colour-only meaning).
- [ ] Backend gates: JUnit for the aggregator + builder output (well-formed XHTML: openhtmltopdf
      is an XML parser), `./gradlew spotlessApply`, 90% coverage.
- [ ] English copy only. Hide a chart when the period has no data instead of drawing an empty one.

# Localization (i18n) — Implementation Plan / TODO

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.
> Spec: `docs/superpowers/specs/2026-07-11-i18n-design.md` (read it first — it holds the
> confirmed requirements, the namespace scheme and all semantics referenced below).
> Branch: `feat/i18n`, cut from **`main`** (house rule: one branch per task, never commit
> to `release/*`/`main`; the user merges manually).

**Goal:** English (default/fallback) + Italian UI with an N-language architecture, plus
locale-aware number/date/currency display and decimal-comma input — the two roadmap
subtasks ("Italian translation", "Locale-aware number and date formats"). Frontend only:
backend errors are translated client-side by mapping RFC-7807 titles; emails/push are a
future backend phase (see spec §5).

**Architecture:** react-i18next with EN+IT JSON catalogs statically bundled (offline-first
PWA untouched); locale = localStorage `app-locale` → `navigator.language` → `en`; a new
central `src/utils/format.ts` (Intl-driven) replaces ~14 inline formatters and the
hardcoded `"it-IT"`/`"en-GB"`/`"en-UK"` locale tags; per-area namespaces extracted
incrementally with **EN rendering byte-identical** so the existing 127 test files pass
unchanged; language UI = new "Preferences" settings section + compact auth-screen switcher.

**Tech Stack:** React 19 + TS + Tailwind 4; new deps `i18next`, `react-i18next`,
`i18next-browser-languagedetector`; existing `date-fns` v4 (add `it` locale wiring);
Vitest + Testing Library; existing `components/ui/` primitives (`CustomSelect`).

## Global Constraints (apply to every task)

- **Language rule (amended by this feature):** code + comments stay **English**. UI copy
  lives in the EN catalogs (source of truth) with IT translations authored in the same
  task. Until Task 21 amends CLAUDE.md, this plan is the authority for the new rule.
- **EN byte-identical invariant:** extraction must not change what EN renders — markup,
  classes, copy byte-for-byte. Existing tests are the spec and must pass unchanged.
  (Single approved exception: Task 5 changes EN money display — see spec decision #6.)
- Frontend gates (run from `frontend/`, same order as CI): `npm run lint` → `npm test`
  → `npm run build`. Tests live under `src/__tests__/` mirroring the source tree. No
  path aliases — relative imports only.
- Extracted pure logic (`format.ts`, `parseDecimal`, error mapper, catalog parity)
  **ships with Vitest unit tests**.
- **Catalog parity:** every task that touches a namespace keeps `it/<ns>.json` key-set
  identical to `en/<ns>.json` (enforced by the parity test from Task 1).
- **UI:** read `frontend/style.md` before any UI task. Reuse `components/ui/` primitives
  (`Button`, `Input`, `CustomSelect`, …) — never hand-rolled `<button>`/`<input>`.
  Theme-aware `app-*` tokens; auth screens are always dark; no colored glow/halos.
- Do **not** kill the running Vite dev server between turns.
- Commit at the end of every task (`feat(i18n): ...` style; extraction-only tasks may
  use `refactor(i18n): ...`).

## Confirmed design decisions (from the interview — do not relitigate)

1. Languages: **EN (default/fallback) + IT**; adding a language = one new catalog, zero code.
2. **Frontend-only scope.** Backend errors mapped client-side; emails/push deferred (spec §5).
3. Library: **react-i18next**, catalogs bundled in the main bundle.
4. Persistence: browser auto-detect + manual override in **localStorage `app-locale`**
   (per-device; `User.locale` arrives with the future backend phase).
5. Display **and** input locale-aware via `Intl.*`; wallet currency code unchanged;
   **CSV import/export stays locale-independent** (out of scope).
6. **Approved EN display change:** money goes from Italian-style `1.234,56` (hardcoded
   `it-IT`) to `1,234.56` in EN; pinned tests updated in Task 5.
7. Rollout **incremental per area**: infra+settings → auth/register → modals →
   dashboard → header/components → admin. App shippable after every phase.
8. Landing fully translated; ToDo/roadmap **chrome only** — `todoData.ts` item texts
   stay English.
9. Language UI: new **"Preferences"** section in `/settings` + compact auth-screen switcher.
10. Branch `feat/i18n` from `main`.

## Phases D–I — String extraction by area

**Standard extraction recipe (applies to every task below):**
1. Create/extend `frontend/src/i18n/locales/{en,it}/<ns>.json`; move the area's literals
   (JSX text, `triggerToast` messages, `aria-label`, `placeholder`, `title`) into the EN
   catalog **byte-identical**, replace with `t("<ns>:key")` via `useTranslation`.
2. Where the area toasts backend errors, route through `mapProblemToMessage` (Task 11).
3. Author the IT translation in the same task (user reviews at merge — native speaker).
4. Existing tests must pass **unchanged** (EN invariant). Add nothing but the parity
   coverage (automatic via Task 1's catalogParity test picking up the new namespace).
5. Full gates → commit `refactor(i18n): extract <area> strings` (+ `feat(i18n): Italian
   translation for <area>` if committed separately).
6. Manual spot-check the area in IT on the dev server before committing.
